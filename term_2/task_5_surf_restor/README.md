# Surface Reconstruction Pipeline

Input data must be stored in `data/` as ASCII `.ply` files with:

- `x y z`
- segment label field such as `scalar_Label`

## Main command

Default entrypoint:

```bash
python3 run_pipeline.py --data-dir data --output-dir outputs
```

This runs the **safe mode** pipeline:

- one cloud is processed per subprocess
- if one cloud crashes or times out, the whole batch does not die
- batch-level results are written to `batch_summary.json`

## Recommended full run

```bash
python3 run_pipeline.py --data-dir data --output-dir outputs_final_500 --max-clouds 500 --timeout 600
```

## Useful examples

Run only first 20 clouds:

```bash
python3 run_pipeline.py --data-dir data --output-dir outputs_stage2 --max-clouds 20 --timeout 600
```

Continue from a later cloud index:

```bash
python3 run_pipeline.py --data-dir data --output-dir outputs_final_500 --start-index 201 --max-clouds 300 --timeout 600
```

## Supported flags

`--data-dir`

- directory with source `.ply` files
- default: `data`

`--output-dir`

- directory for reconstructed meshes and summaries
- default: `outputs`

`--max-clouds`

- limit number of processed clouds
- default: process all found files

`--min-segment-points`

- discard segments smaller than this threshold
- default: `64`

`--downsample-voxel`

- optional voxel size for preprocessing downsampling
- default: disabled

`--start-index`

- 1-based index of first cloud to process
- useful for continuing a long run
- default: `1`

`--timeout`

- per-cloud timeout in seconds in safe mode
- default: `600`

`--unsafe-direct`

- disables safe subprocess mode
- runs the legacy single-process pipeline directly

## Output structure

Inside `--output-dir`:

- one subdirectory per cloud
- per-segment reconstructed `.ply` meshes
- assembled cloud mesh
- `batch_summary.json` for the whole run

In direct mode, the output also includes per-cloud `summary.json` files generated by the pipeline.
